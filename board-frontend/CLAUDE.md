This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

React 19 + TypeScript + Vite 7 SPA (react-router-dom 7, lucide-react) — a small bulletin board frontend meant to plug into a separate Kotlin/Spring Boot backend (not in this repo). UI text and docs are in Korean. The project root is `board-frontend/`; it is not a git repo.

## Commands

```bash
npm ci
cp .env.example .env     # first time only
npm run dev              # http://127.0.0.1:5173 (strictPort — fails if 5173 is taken)
npm run typecheck        # tsc -b
npm run build            # tsc -b && vite build → dist/
npm run preview
```

No test runner or linter is configured. Verification = `npm run typecheck` / `npm run build` plus manual run in the browser.

Node 22.12+ (or 20.19+) required by Vite 7.

## Architecture

**Two interchangeable API backends behind one `api` object.** `src/lib/api.ts` exports `api = USE_MOCK ? mockApi : realApi`. `realApi` is typed as `typeof mockApi`, so `src/lib/mock.ts` (localStorage-backed demo) defines the contract and both must keep the same method signatures (`signup, login, me, listPosts, getPost, createPost, updatePost, deletePost`). Pages and `auth.tsx` only ever call `api.*`.

- `VITE_USE_MOCK` (default **true** unless exactly `'false'`) and `VITE_API_BASE_URL` are read in `src/lib/config.ts`. Env changes need a Vite restart / rebuild.
- Wire format (paths, JSON fields, status codes) is specified in `API.md`; responses are returned unwrapped (no `{data: ...}`). Changing the backend shape → edit `realApi` in `api.ts`, `src/types.ts`, and limits in `src/lib/validation.ts` (these should mirror the limits in `API.md`).
- Errors: `request()` in `api.ts` normalizes everything into `ApiError(message, status, fieldErrors?)`; `errorMessage()` in `config.ts` extracts display text. `fieldErrors` from the server are meant for per-field form messages.

**Auth/session.** `AuthProvider` (`lib/auth.tsx`) holds `user`, `loading`, `sessionError`. On mount it calls `api.me()` if a token exists. A 401 on an authenticated request clears the token and dispatches a `board:session-expired` window event, which `AuthProvider` listens for (toast + clear user). Token storage: mock → `localStorage` (`board.demo.token.v1`), real API → `sessionStorage` keyed by API base URL; demo and real tokens never mix. Mock DB lives in localStorage key `board.demo.database.v1`.

**Routing** is a single `createBrowserRouter` in `src/App.tsx` under `components/Layout`. `posts/new` and `posts/:id/edit` are wrapped in `Protected`, which redirects to `/login?next=<path>`. Author-only edit/delete is enforced by the backend (and mimicked in mock); the UI also hides controls for non-authors.

**Layout of code:** `pages/` (Board, Auth, Post, Editor), `components/` (Layout, Toast, ConfirmDialog, States), `lib/` (api, auth, config, mock, validation, format), single global `styles.css`. Code style is dense/compact (multiple statements per line); match it when editing.

## Notes

- `dist/` is generated by `npm run build`; don't hand-edit.
- Direct access to deep links (`/posts/1`) needs SPA fallback to `index.html` on any hosting server.
- Out of scope by design: password reset, email verification, refresh tokens, attachments, comments, admin.
